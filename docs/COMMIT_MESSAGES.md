## feat: AI question-generation pipeline + no-repeat quiz serving

| Commit | `a0f8d2c93e8978c79a818dabdb358b1074f6ddd6` |
| Author | devgeereact <292055051+devgeereact@users.noreply.github.com> |
| Date | 2026-07-20 23:22 |

Adds the backend spine for an owned, curriculum-grounded question pool and the
"a child never sees the same question twice in 12 hours" rule.

Content strategy: import the free England National Curriculum objectives as the
topic skeleton and AI-generate questions against them (owned, correct, unlimited)
— not scraping copyrighted question banks into a kids' SRS engine.

Schema (migration 0004, additive — existing rows default to published):
- curriculum_objectives: the NC objective spine questions are generated against
- quiz_questions: + status (draft|published|rejected), objectiveId, difficulty,
  source. Generated questions land as draft, invisible to children until reviewed.
- question_impressions: one upserted row per (child, question), the no-repeat ledger

Generation:
- lib/quiz-validate.ts: strict runtime validation of LLM output against the
  MixedQuestion union — rejects unanswerable shapes (answer out of range, dup
  match sides, etc.), never stores what it can't verify
- lib/openrouter.ts: server-side generator; drops bad questions, keeps the batch
- api/admin/generate: token-gated, inserts validated questions as draft

Serving:
- api/quiz: authed, child-aware. Excludes anything seen in 12h, shuffles the
  remainder, re-shuffles mcq/multi options to kill positional guessing, records
  impressions. Falls back to oldest-seen when the pool is exhausted in-window.

Security: unify admin routes on a shared fail-closed guard (db/admin-auth.ts,
ADMIN_TOKEN); seed migrated off its ad-hoc guard onto it.

Verified: tsc --noEmit clean, expo lint clean, expo export bundles all 8 API
routes. Not yet run against a live DB (needs deploy) and client is not yet wired.

## chore(tooling): add rule-guard hooks and content-integrity checks

No tests and no CI exist here, so tsc and lint were the only automated gates,
enforced by a human remembering. These make the AGENTS.md rules and two content
invariants structural instead.

Hooks (.claude/settings.json -> scripts/hooks/):
- guard-destructive: blocks the irreversible db/clerk scripts unless an explicit
  confirmation flag is passed, npm-installing Expo packages (npx expo install
  pins to the SDK), edits to ios/ or android/ (CNG regenerates them), unsigned
  simulator builds (empty entitlements -> Keychain failure -> permanent splash
  hang), and the schema generator in a non-TTY shell where it hangs on a prompt.
- guard-patterns: blocks StyleSheet.create, inline style props, @react-navigation
  imports, empty catch, raw hex and arbitrary Tailwind values.
- privacy-claim: fires when package.json gains a dependency, because
  src/app/data-usage.tsx makes a factual claim to parents about carrying no ad,
  analytics or tracking SDK.
- done-gate: a turn cannot end on a red tsc/lint or a failing content check.

Both pattern guards ignore their own subject matter when it appears as data --
in comments, quoted strings or heredoc bodies. Three rules tripped on their own
documentation before that was added, and a guard that punishes explaining the
rule is one that gets switched off, taking the useful checks with it.

Checks (npm run check:content):
- check-strands: a set's topic/strand must equal a curriculum strand name,
  because lib/analytics.ts matches them by string equality. 10 of 27 sets did
  not, so real content was invisible in the hub that exists to show it.
- check-answer-bias: no quiz may cluster its correct answers on one option
  position. Two were 100% option A -- passable without reading, and the false
  result feeds the spaced-repetition schedule.

## fix(study): quiz scoring recorded the wrong answer, and session mode recorded nothing

| | |
|---|---|
| Commit | `8ee30b3d6c659353a42acbde55f079ab40b4a483` |
| Author | Gideon Akinlotan <info@gakinz.com> |
| Date | 2026-08-16 05:33 |

Two P0s, both found by driving the app rather than reading it, and both invisible
to a typecheck.

1. Quiz scoring. quiz/[id].tsx listed Clerk's getToken in the serving effect's
   dependency array. Clerk returns a new closure on nearly every render, so the
   effect refired constantly, refetched, and api/quiz reshuffled the options --
   by design, so a child cannot memorise a position -- AFTER the child had read
   them. The tapped index then pointed at a different option. A quiz answered
   entirely correctly scored 1/5, with a screenshot showing "Yesterday" tapped
   and "Happily" recorded. getToken now lives in a ref synced by its own effect.

   This was dormant until today: api/quiz was 500ing on an unapplied migration,
   so served-quiz.ts fell back to the stable local list and hid it. Fixing the
   backend activated it.

2. Study-session mode never persisted. rateCard/recordSession were called only
   from the flashcard runner; the session flow imported useProgress and read
   from it without ever writing. Six correct answers produced "Cards studied 0"
   on the session's own summary, and every progress surface showed the set as
   untouched. rateCard now fires per answer and recordSession on the last card.

   lib/study-session.ts is new because the session spans one screen per card via
   router.replace, so a ref cannot hold the clock the way the flashcard runner's
   does.

Verified on device: 5/5 and "Cards studied 6". Regression flows in .maestro/
(13 and 14) reproduce both. Flow 14 asserts the invariant that actually broke --
the option recorded equals the option tapped -- rather than specific answers,
because the 12-hour no-repeat rule serves different questions on a second run and
any flow hardcoding an answer has a 12-hour shelf life.

## feat(privacy): erase child and account data on the server, not just on the device

| | |
|---|---|
| Commit | `0a5d321bd4730765a6453b1aff5dca003a22aa8f` |
| Author | Gideon Akinlotan <info@gakinz.com> |
| Date | 2026-08-16 05:33 |

Deleting a child removed one entry from Clerk unsafeMetadata and nothing else.
The Postgres children row -- created lazily by db/auth.ts on first sync -- and
every reviews, sessions, certificates and question_impressions row hanging off it
survived. There was no DELETE anywhere in the codebase, so the data was not
merely orphaned: it was unreachable and unremovable.

That made delete-account.tsx's promise false. It tells a parent that deletion
"erases everything below, immediately and permanently", listing child profiles,
all learning history and certificates, while deleting only the Clerk user and
three on-device stores. A false statement to a parent about a child's data is
what GDPR Article 17 and the UK Children's Code attach to, not a missing feature.

Added:
- DELETE /api/children/:clientId -- resolves the child by (verified parent,
  clientId) together, so it cannot reach another family's. Idempotent: an unknown
  id returns 200 {deleted:false}, so a retry after a dropped connection cannot
  fail and a caller cannot probe which ids exist.
- DELETE /api/account -- every child for the parent, plus the subscriptions row,
  which is keyed by clerk_user_id and so is NOT reached by the child cascade. It
  has no writer today; erasure must not depend on which features happen to be
  wired yet.
- lib/reviews.ts clearChildProgress for the per-child local record.

Ordering is the whole fix, in both directions:
- removeChild calls the server BEFORE touching Clerk metadata, because that entry
  holds the only copy of the clientId; removing it first would orphan the server
  row beyond naming.
- delete-account calls the server BEFORE user.delete(), because user.delete()
  destroys the session token that is the only thing able to authorise the
  erasure. It now aborts the whole deletion if that call fails, rather than
  proceeding to a partial wipe it would then describe as complete.

data-export.tsx now includes the server rows (gokid.export.v2). Its own docstring
had predicted this: "if a third store is ever added, it has to be added here too,
or this screen quietly starts lying about being complete."

Cascade proven against the live database: a scratch child with 1 review, 1
session and 1 certificate went 1/1/1 -> 0/0/0 on deleting the child row.

## fix(content): make sets visible to their own curriculum, and quizzes unguessable

| | |
|---|---|
| Commit | `2e349d2ba20a62d280d435ce761580258ac30c36` |
| Author | Gideon Akinlotan <info@gakinz.com> |
| Date | 2026-08-16 05:34 |

Four content-integrity defects, three of which were invisible to every prior
review because none of them exists in a single item -- only in the set of items.

1. Answer-position bias. Two quizzes had the correct answer at option A for all
   five questions; seven more clustered on one index. A child scores full marks
   by always tapping the same position, and that false result is written into the
   spaced-repetition schedule, so the quiz stops measuring and starts corrupting
   what the child is shown next. 21 questions across 9 quizzes reordered; the
   correct answer TEXT is unchanged in all 135 questions, verified by diffing
   against a pre-edit snapshot.

2. Strand mismatch. lib/analytics.ts groups sets by matching StudySet.topic to a
   subject strand name with exact string equality. 10 of 27 sets matched nothing,
   so correctly authored content was invisible in the subject hub, in search, and
   in the strong/weak-area nudges. Rather than retitle ten sets and lose the
   specific wording a parent recognises, StudySet gains an optional `strand`:
   topic stays "Fronted adverbials and punctuation" for display, strand is
   "Grammar and punctuation" for grouping, and strandOf() is the single accessor.
   subjects.ts gains the statutory strands that had authored sets and nowhere to
   land -- Seasonal changes, Living things and their habitats, States of matter,
   Ratio and proportion, Algebra -- and "Animals and humans" becomes the DfE's
   actual "Animals, including humans", which matters because the NC wording
   deliberately classifies humans as animals and the old phrasing taught the
   misconception back.

3. Objectives disconnected from content. Y3 Geography's objectives named UK
   counties and rivers/mountains while its only set teaches European capitals --
   and rivers/mountains is verbatim the Y5 set's topic. Y3 Science never
   mentioned skeletons though its only set is the skeleton. Four more sections
   had the same shape. The keep-vs-remove rule is now written into the file:
   an untaught objective stays as honest coverage information when it is real
   curriculum content AND something else in its list is actually taught.

4. The generation prompt claimed UK alignment but never forbade American
   spelling or vocabulary, and never constrained where the correct answer sits.
   Both defects found by hand in the authored content would have reproduced in
   every generated batch. Fixing the prompt is worth more than fixing the nine
   quizzes.

Guarded by npm run check:content so none of this can drift back silently.

control that cannot do what it implies. These were the remaining breaches.

  the same class as the "GoKid Plus" literal already fixed.

- Tapping a scheduled reminder went nowhere: reminders.ts schedules a real OS
  notification but nothing registered a response listener, so a live entry point
  into the app led to no particular screen. It now lands on the study dashboard.

  reminders.ts uses it; the false claim had also been copied into a second file.

nextSetId wrapped at the end of the curriculum, and on device it sent a Year 4
child into Year 3 content -- the "next set" suggestion actively regressed the
year group. It now takes the child's year, clamps instead of wrapping, and both
